Shared, durable memory for every agent in the homelab.

Claude Code sessions, Copilot, and pipeline agents all start from zero. klams is the store they check first and write back to — machines, services, past decisions, gotchas — so a lesson learned once, by anyone, is recallable by everyone, months later, from a two-line search. Rust service on kubs0; agents reach it over MCP; two scanners keep it fed with everything in the repos.

Three kinds of memory, three write disciplines

knowledge 180,553

Embedded semantic content. Two supplies: deliberate agent writes (memory_add) and bulk scanner ingest from every repo on both machines. Searched by meaning, ranked by provenance.

facts 38

Typed, validated key/value state with versioned amendments, source-trust ranking, and a dissent queue — a lower-trust writer can't silently overwrite canon.

events 27

Append-only observations: service state transitions, run reports. Immutable by design — history, not belief.

The read path — what a search actually does

1embedQwen3-Embedding on the GPU, instruct prefix on the query
2retrieve ×3global ANN + a curated-only stratum + Postgres FTS for facts/events
3gate & weightcurated boost only when competitive (0.82 × top score); hand-written 2.0 · extracted 1.5 · bulk 1.0; stale volatile memories demoted
4collapseduplicates fold by content hash — the page never spends two slots on one fact
5rerankbge-reranker-v2-m3 cross-encoder re-reads the candidates · ~35 ms · best-effort
6fuseweighted reciprocal-rank fusion across all four lists → one ranked page

Every search is also logged (query, caller, scores) — the store measures itself, and those logs are where the next eval cases come from.

Proof it improves — the eval is the contract

Every ranking change is a measured change. The suite is real agent queries with pinned answers — "which memory must win, at what rank" — run against the live corpus before anything merges.

When it saturated at 21/21, it was grown until it could fail again: supersession under paraphrase, provenance repair bars, cases mined from live traffic. Turn the reranker off and it drops to 24/27 — the instrument discriminates.

Misses are logged, sampled, and harvested — the eval eats real traffic, not invented benchmarks.

Memory that can change its mind

memory_supersedeone call replaces a stale record: new one written, old one hidden with a pointer trail. A superseded belief stays gone — even when you ask with different words.
memory_updateauthors fix their own records in place; the text re-embeds automatically.
similar-on-writea new memory that near-duplicates an existing one comes back with the match — reconcile at the only moment it's cheap.
volatilitydeclare a memory volatile (an IP, a version) and it ages out of ranking on a half-life; stable truths never decay.

Why it's credible

Built sprint by sprint since 2026-05-16 — 33 sprints, each a reviewed PR with its intent and outcome recorded in-repo. The store runs its own instruments: every search sampled, misses classified, oversized writes kept. When a deep review found the corpus 44% duplicates and the ranking unmeasurable (2026-07-25), the next six sprints rebuilt the corpus (44% → 0.11% duplicates), swapped the embedder onto the GPU, added provenance ranking, lifecycle verbs, and a reranker — each step gated by the eval — and a retrospective then re-derived every calibrated constant against live data. The docs describe the system as it is; the diagrams are drawn from what exists.
