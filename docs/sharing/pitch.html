Thought stage — a brainstorm, not a commitment

What if your memory store had peers?

Not a general knowledge store — we have the Internet for that. A share among people whose interests overlap: the hard problems Alice has solved are likely related to the hard problems Bob will encounter.

01Two brainstorms, one design

#760

Community shared store

A cloud store a community reads from and contributes curated memories to. Query both, keep X% from local.

＋
#768

Curated exfil digests

An agent periodically selects the deep gotchas, sanitizes them, and publishes a digest others can ingest.

The digest is the primitive; the shared store is a view over subscribed digests. Both need the same three things: selection, sanitization, and a portable record format. The rest is topology.

02Publication, not access

Nobody writes into anyone else's instance — each operator publishes a small, signed, static feed; everyone else subscribes. The community is just a reviewable feed list. Retrieval never leaves your machine.

03Nothing leaves without passing five gates

1Selecthand-authored tier only; "took a lot of research" signals; share:never is a veto
2Generalizerewrite out hostnames, paths, tailnet names — or drop the record
3Scrubsecret + PII scanners, fail closed
4Human approvalevery digest is a reviewed PR — non-negotiable in v0
5Sign & publishminisign manifest → static hosting

Loop prevention is schema, not policy: only origin = local records are selectable, ever. What came in from a feed can't flow back out.

04At query time: a sixth rank list, not a second query

Ingested community memories are ordinary local knowledge points. They enter the existing one-pipeline retrieval as their own provenance tier — below your own hand-written notes, above scanner bulk — and a quota caps how much of any page they may take (default: keep 80% local).

05The missing piece is a standard — so draft one

0

adopted cross-system memory interchange standards exist (July 2026 survey). What exists is a land-grab of one-author drafts, all from May–July 2026 — two colliding "PAM"s, two colliding "AMP"s, and a weeks-old W3C community group with nothing published.

Letta .af — whole-agent checkpoints; archival memory unsupported
memorywire — API verbs, not a portable record
agentmemoryprotocol — markdown-first like us, v0.1, one startup
PAMSPEC IETF I-D — great field vocabulary, zero adoption

Memory Feed (draft v0.1) — markdown + minimal metadata, tiny required core, namespaced extensions, signed manifests, normative loop-prevention. Written so no part requires klams; if a real standard wins later, we adopt it and call that success.

07Honest about sequencing
